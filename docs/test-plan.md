# Тест-план: Bank API

## 1. Цель

Проверить, что REST-сервис банковских счетов ведёт себя в соответствии с `docs/requirements.md`:
корректно создаёт счета, проводит операции, не теряет деньги и согласованно хранит данные в БД.

## 2. Объект тестирования

Сервис `service` (Spring Boot + PostgreSQL). Методы: создание и получение счёта, пополнение, снятие, заморозка и разморозка, перевод.

## 3. Границы

**Входит:** функциональное тестирование API, негативные и граничные сценарии, проверка данных в БД, согласованность ответов API и БД.
**Не входит:** нагрузочное тестирование (отдельный этап), безопасность и авторизация (в сервисе их нет), UI.

## 4. Подход

1. Ручное исследовательское тестирование через Swagger UI и Postman, чек-лист в `docs/checklist.md`.
2. Тест-кейсы в `docs/api-test-cases.md`, приоритеты H, M, L.
3. Автоматизация на Groovy + Spock + REST Assured, проверка БД через SQL (`groovy.sql.Sql`).
4. Дефекты оформляются в `docs/bug-reports`, серьёзность по шкале Blocker / Critical / Major / Minor / Trivial.

## 5. Окружение

JDK 17+, Maven, Docker (PostgreSQL 16 из `docker-compose.yml`). Сервис запускается локально на порту 8080.

## 6. Критерии

**Начало:** сервис и БД запущены, Swagger UI доступен.
**Завершение:** все кейсы приоритета H и M выполнены, дефекты оформлены, сводка по покрытию в `docs/api-test-cases.md` актуальна.

## 7. Риски

- Данные в БД накапливаются между прогонами: тесты не должны зависеть от чужих счетов и создают свои.
- Тесты работают с реальной БД, поэтому нельзя запускать их на общей базе.

## 8. Отчётность

Статусы кейсов в `docs/api-test-cases.md`, реестр дефектов в `docs/bug-reports/README.md`.
